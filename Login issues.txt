 Google AI Studio Prompt — Fix 1-Day Pro Entitlement Persistence

You are a senior full-stack engineer. Investigate and fix the existing 1-Day Pro subscription/entitlement system in this application.

 ## Business Requirement

 The application has a **1-Day Pro** plan that includes these four features:

 - AI Career Coach
- ATS Match
- Tailor CV
- Cover Letter

 A user must receive access to these features **only after a successful payment has been confirmed**.

 Once payment is successfully confirmed, the user receives **exactly 24 hours of Pro access** starting from the confirmed entitlement start time.

 The user's Pro access must persist for the entire 24-hour period regardless of:

 - Page refresh/reload
- Logout and login
- Closing and reopening the browser
- Starting a new session
- Using another device/browser while logged into the same account

 The user must NOT be downgraded to Free simply because React state has reset, localStorage is empty, Firestore temporarily reports a default value, or subscription verification is still in progress.

 # Current Problem

 The current implementation appears to have an entitlement race condition.

 On page refresh, React initializes something similar to:

```
const [isPremium, setIsPremium] = useState(false);
```

 This immediately treats the user as Free before the subscription/entitlement has been verified.

 A Firestore `onSnapshot` listener can then return `isPremium: false` before `/api/user/subscription` finishes verifying the user's actual paid entitlement.

 The application then calls `updateTier()` or equivalent logic, which can overwrite the user's Pro state and/or localStorage.

 Similar problems occur during logout/login, browser restart, and new sessions.

 This must be fixed at the architecture level rather than by simply hiding/showing UI elements.
